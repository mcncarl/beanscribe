# 使用和真机验收

## 第一次连接

1. 给录音豆充电、开机，放在手机附近；确认手机蓝牙开启。
2. 从飞书工作台或底部「录音豆」打开应用，让飞书完成本人登录。
3. 进入设备页，点连接，允许飞书使用蓝牙，在扫描结果中选自己的 D3200。
4. 等待连接与握手完成，确认设备信息出现。仅看到扫描结果，不代表音频通道已经成功。
5. 若设备被其他手机或应用占用，先在你控制的那一端正常断开，再尝试。不要为了连接而盲目解绑、重置或刷固件。

页面会记住连接偏好；明确点断开后不会继续按旧偏好自动连接。另一应用使用过设备时，下一段录音可能需要重新协商密钥，这是预期的兼容步骤。

## 选择识别方式

在设置里选择实时识别和录后识别服务。未配置豆包时只能用 StepFun。

- 实时 StepFun/豆包：接收期间出现文字，录后可以再识别全文。
- 只录音：接收并保存音频，不产生实时字幕；是否自动识别全文取决于录后设置。
- 录后全文识别：处理已经保存到服务器的 WAV，返回发言人等结果。可以先预览、再应用；自动应用按你的设置执行。
- 总结、章节、翻译：由 StepFun 文本服务处理。自动飞书文档同样依赖这条文本能力。

实际标签以当前页面为准；所有切换仅影响本应用，不改变原厂应用的处理方式。

## 第一段录音

1. 先确认设备已连接，页面处于等待/可接收状态。
2. 按录音豆实体键开始录音。若页面提供「开始接收」，先进入接收等待，再按实体键。
3. 等待页面显示正在录音、时间增长；先等几秒，再说一段不含隐私的测试内容。
4. 观察实时字幕是否在说话过程中逐步出现。只录音模式下不要求有文字。
5. 按**实体键**结束设备录音，等待手机完成接收和保存。
6. 如果只点了网页「停止并保存」，查看是否提示设备还在录音；仍需按实体键停止。震动提醒不能代替停止设备。
7. 从列表重开刚才的录音，播放、拖动进度，核对实际声音、时长和文字。

在已测试的固件上，实时读取从当前录音位置开始，开头可能漏掉约 2–4 秒。设备本地文件可能保留这些声音，但本项目目前不会自动补回。对不能遗漏开场的场景，必须先用自己的设备验证并保留原始录音。

## 完成一轮验收

| 检查 | 通过标准 |
| --- | --- |
| 登录和导航 | 从消息页底部一键打开，退出重开后位置、名称和录音库正常 |
| 身份限制 | 未登录访问录音 API 得到 401；非配置账号不能进入 |
| 设备 | 连接成功、设备状态可见；换设备时不能误读其他设备 |
| 实时内容 | 至少一段 30–60 秒短录音，字幕在录音结束前更新 |
| 保存 | 实体键停止后，页面显示已保存；退出重开音频和文字仍存在 |
| 播放和编辑 | 播放有声音、时间可拖动；改标题/正文后重开仍保留 |
| 导出 | TXT、SRT、WAV 下载成功，导出的音频能播放 |
| 自动文档 | 开启后生成私人文档，本人能打开，未授权者不能访问 |
| 录后识别 | 结果可预览、应用，并能识别真实说话人；按自己的音频核对质量 |

基础验收通过后，再逐步测试锁屏、切换 App、弱网和更长录音。iOS 后台策略、设备固件、蓝牙质量和提供商限制都会影响结果。短录音通过不能代替长录音验收。

## 文件管理和日常维护

- 录音的服务端副本在 `data/recordings/`，包括 WAV、文字、元数据和任务状态。单独备份整个数据目录，并限制备份访问权限。
- 手机端缓存有助于重开页面，但不要把它当作唯一备份。
- 设备页的「管理录音豆里的录音」操作的是**硬件存储**。先播放核对服务器副本；只存在硬件中的文件删掉后无法从本项目恢复。正在录音的文件不可勾选删除。
- 文档权限由服务端先设置、回读，再写入正文。失败或远端编辑冲突会停止，不会默默覆盖已修改文档。
- 维护或重启服务前先结束录音并等处理任务完成，避免主动中断正在采集的声音。

本项目没有固件升级、刷写、按键重映射或原厂 ASR 关闭功能。不要把网页导航入口的变化理解为设备固件已经改变。
